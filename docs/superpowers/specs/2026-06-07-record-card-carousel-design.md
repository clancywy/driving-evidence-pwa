# 处理记录卡片横滑设计

## 背景

当前 `处理记录` 页面用纵向列表显示所有记录。用户希望把记录改成卡片样式，并通过左右滑动切换。已确认采用方案 A：每屏一张主卡片，左右略露出相邻卡片，形成 iOS 风格的横向卡片轮播。

## 范围

本次只调整 `处理记录` 页面中记录列表的展示和滑动方式。

包含：

- 将记录列表改为横向滑动卡片轨道。
- 每张记录卡片保持现有内容：时间、日期、处理状态、地图、打开地图链接、车牌号、备注、保存补充信息按钮。
- 当前主卡片占主要宽度，左右保留少量空间露出相邻卡片。
- 滑动时自动吸附到卡片边界。
- 保留空状态 `暂无记录`。

不包含：

- 不新增删除记录功能。
- 不改变记录保存逻辑。
- 不改变定位和地图坐标逻辑。
- 不引入第三方轮播库。

## 交互

- 用户进入 `处理记录` 后，看到第一张记录卡片。
- 在手机上左右滑动卡片区域，可以切换上一条或下一条记录。
- 滑动停止后，页面吸附到最近的一张卡片。
- 车牌号、备注和保存按钮仍在当前卡片内正常使用。
- 没有记录时，不显示横滑轨道，只显示空状态。

## 视觉

- 延续当前 PWA 的 iOS 风格：浅灰背景、白色卡片、系统字体、8px 圆角、轻阴影。
- 卡片宽度使用屏幕宽度的约 86% 到 88%，让相邻卡片边缘可见。
- 卡片之间保留清晰间距，避免输入框和地图贴边。
- 处理记录标题和数量徽标保持现状。

## 技术设计

- 使用 CSS 原生横向滚动：
  - `overflow-x: auto`
  - `scroll-snap-type: x mandatory`
  - 每张 `.record-card` 使用 `scroll-snap-align: center`
- `renderRecords()` 仍按当前记录数组渲染卡片，不新增复杂轮播状态。
- 仅在 CSS 中改变 `.record-list` 和 `.record-card` 的布局规则。
- 如需让输入框在卡片中稳定显示，限制卡片为固定收缩行为，避免横向内容撑开。

## 验收标准

- `处理记录` 有多条记录时，记录以横向卡片显示。
- 当前卡片居中，左右能看到相邻卡片边缘。
- 手机上可以左右滑动切换记录。
- 滑动后能自动吸附到一张卡片。
- 车牌号和备注仍可输入并保存。
- 空记录状态仍显示 `暂无记录`。
- 自动测试和 JS 语法检查通过。
